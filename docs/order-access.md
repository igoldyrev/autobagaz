# Доступ покупателя к заказу

Покупательская страница `/checkout/{access_token}/success` открывается по
секретному токену из 32 криптографически случайных байтов (64 hex-символа).
Токен создаётся сервером отдельно от `checkout_token`, который отвечает за
повторную отправку формы. Ссылки формируются через `Order::customerUrl()`;
административные маршруты продолжают использовать числовой ID и существующую
проверку прав.

После оформления покупатель перенаправляется на `/checkout/thanks` без
токенов в адресе. Кнопка «Открыть заказ» ведёт на `/checkout/open-order`:
сервер берёт заказ из сессии оформления и перенаправляет на секретную ссылку.
Оба адреса требуют сессию оформления и не принимают ID или токен заказа
из параметров запроса. При отсутствии заказа в сессии возвращается 404.
В сессии доступен последний оформленный заказ; для остальных остаются ссылки
из писем. Секретная ссылка включена в существующее письмо о получении заявки.
Она работает без
исходной браузерной сессии и не имеет срока действия: любой её обладатель
получает доступ к покупательской странице заказа. В письме есть предупреждение
не передавать ссылку другим людям. Токены скрыты при сериализации модели.

Числовой ID, номер заказа и токен оформления не дают доступа к странице.
Некорректные и неизвестные токены возвращают 404. На защищённой странице
установлены `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`
и запрет индексации. Метрика на этой странице отключена, чтобы секретный URL
не передавался в аналитику.

## Цель оформления

Цель `order_created` выводится только на `/checkout/thanks` после создания
нового заказа. В сессии сохраняется одноразовый признак создания, который
потребляется при открытии этой страницы под блокировкой сессии. Обновление
страницы, открытие секретной ссылки и повторная отправка того же оформления
не создают новую цель. Промежуточный переход на другую страницу не отправляет
цель оформления и не потребляет этот признак.

Страница благодарности не получает модель заказа: в HTML нет номера, контактов,
токена оформления или секретной ссылки. В конфигурацию Метрики передаются
только `order_created`, `order_price` и `currency: RUB`. Для этой страницы также
запрещены кеширование, индексация и передача Referer.

Отправка использует существующий `analytics.js` и правила согласия:
без действующего согласия счётчик не загружается и цель не отправляется;
при последующем согласии пропущенная цель не воспроизводится. Одноразовый
признак предотвращает повторы на стороне приложения, но не гарантирует доставку
в Метрику при блокировщике, сетевом сбое или уходе со страницы.

## Выкладка

До открытия обновлённого приложения для запросов применить миграцию
`2026_10_23_000000_add_access_token_to_orders_table.php`. Она выдаёт отдельный
токен каждому существующему заказу, сохраняя остальные данные. Миграция
не рассылает письма старым покупателям. Старые ссылки по числовому ID
перестают работать. Если маршруты кешируются, пересобрать кеш маршрутов.

Страница заказа показывает исходные товары и условия, последнюю согласованную
версию и новое предложение менеджера. Подтверждение выполняется отдельным POST
по тому же секретному токену; проверка доступа предшествует обработке согласия.
Страница и действие согласования не подключают Метрику. Будущая оплата должна
использовать такую же проверку доступа; сама оплата пока не реализована.
