# Индексация и переход на основной домен

Основной адрес для canonical и sitemap — `https://autobagaz.ru`.
Настройки находятся в `config/seo.php`:

- `SEO_CANONICAL_URL=https://autobagaz.ru` — основной адрес сайта, без завершающего `/`.
- `SEO_INDEXING_ENABLED=true` — разрешение индексации только на хосте основного адреса.
  Значение `false` закрывает от индексации и основной домен.

На `new.autobagaz.ru` и остальных хостах приложение отдаёт `X-Robots-Tag:
noindex, nofollow`, метатег публичных HTML-страниц запрещает индексацию,
`robots.txt` содержит `Disallow: /`, а sitemap возвращает 404.
Правило не зависит от `APP_ENV`: production-окружение тестового сайта не открывает индексацию.
Статические ресурсы, которые веб-сервер отдаёт без Laravel, заголовком приложения
не покрываются. Запрет индексации не заменяет ограничение доступа к данным.

## Основной домен

- Публичные страницы получают canonical с основным HTTPS-адресом.
- Параметры рекламы (`utm_*`, `gclid`, `yclid`, `_openstat`) не включаются в canonical.
- Номер страницы каталога или акций `page > 1` сохраняется в canonical;
  первая страница указывает на URL без `page=1`.
- Прочие параметры, включая фильтры, сортировку и выбор автомобиля, дают
  `noindex,follow`. Такие URL не добавляются в sitemap.
- Админка, включая вход и ответы с перенаправлением на вход, корзина, оформление,
  страницы заказа, внутренние API и остальные служебные маршруты получают
  `X-Robots-Tag: noindex, nofollow`. У HTML корзины и оформления также есть метатег.
  Для служебных страниц canonical не выводится.
- Ответы с HTTP-кодами 4xx/5xx получают запрещающий индексацию заголовок.

На основном домене `robots.txt` позволяет обход: поисковый робот должен получить
страницу, чтобы прочитать её `noindex`. Поэтому запрет для админки и оформления
реализован заголовками и метатегами, а не `Disallow`.
См. [документацию Google](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

## Sitemap

`/sitemap.xml` — XML-индекс карт `/sitemaps/1.xml`, `/sitemaps/2.xml` и далее.
В каждой карте не более 1000 URL. Список формируется из текущих данных:
информационные страницы, основные разделы каталога, активные товары (включая
товары с нулевым остатком), активные специальные категории, марки, модели,
поколения и конфигурации. Неактивный родитель исключает дочерние страницы.
Даты изменения не добавляются: достоверная общая дата изменения содержимого
страницы сейчас не отслеживается.

## Выкладка и переключение домена

1. При выкладке удалить прежний `public/robots.txt`: иначе веб-сервер отдаст
   статический файл вместо маршрута Laravel. Штатный SFTP-деплой учитывает удаления
   файлов по манифесту. Обновить кеши конфигурации, маршрутов и представлений.
2. До переключения домена проверить `new.autobagaz.ru`: запрещающие заголовок
   и метатег, `Disallow: /` в robots и HTTP 404 у sitemap.
3. При переходе установить `APP_URL=https://autobagaz.ru`, оставить
   `SEO_CANONICAL_URL=https://autobagaz.ru` и `SEO_INDEXING_ENABLED=true`,
   обновить кеш конфигурации. Старую версию сайта заменить новой только после
   приёмки и подготовки соответствий старых URL новым.
4. На хостинге настроить HTTPS и постоянные перенаправления с HTTP, `www`
   и тестового домена на соответствующие страницы основного адреса.
   Сопоставление старых URL и эти серверные перенаправления — отдельная работа.
5. На основном домене проверить canonical, robots, sitemap и запрет индексации
   админки и оформления. Отправить `/sitemap.xml` в панели поисковых систем.

Локальная проверка: `php artisan test --filter=SeoTest`.
Изменения в коде сами по себе не подтверждают выкладку и проверку на хостинге.

## Структурированные данные

JSON-LD формируется на сервере. На публичных страницах добавлен `AutoPartsStore`
(подтип Organization) с названием, основным URL, логотипом, публичными контактами,
адресом и расписанием из `config/orders.php`. Продавец в предложении товара
ссылается на этот же объект через `@id`.

В карточке активного товара добавлены `Product` и `Offer`: фактические название,
описание, фотографии, производитель, модель, цена в RUB и основной URL карточки.
Не заполненные необязательные поля пропускаются. Положительный остаток означает
`InStock`, нулевой — `OutOfStock`: пометка «Под заказ» не считается гарантией поставки.
Цена с копейками отображается на карточке без округления до целых рублей,
чтобы совпадать с предложением в JSON-LD. Вымышленные рейтинги, отзывы, артикулы,
сроки действия цены и условия доставки не добавляются.

Компонент `breadcrumbs` строит видимую цепочку и `BreadcrumbList` из одного списка.
Названия и порядок совпадают; ссылки в JSON-LD используют основной домен.
Последний элемент без ссылки обозначает текущую страницу.
Все значения JSON-LD кодируются с экранированием HTML-символов, в том числе
закрывающего тега script. Служебные страницы разметку не получают.

Проверка: `php artisan test --filter=StructuredDataTest`.
Тесты проверяют декодирование JSON, цену и наличие, отсутствие вымышленных полей,
защиту от выхода из script и совпадение крошек на 18 публичных страницах.
После выкладки нужно отдельно проверить реальные карточки и цепочки в
[Google Rich Results Test](https://search.google.com/test/rich-results)
и [Schema.org Validator](https://validator.schema.org/).
Эти внешние проверки в локальные тесты не входят.

Справочники: [Product и Offer](https://developers.google.com/search/docs/appearance/structured-data/product-snippet),
[BreadcrumbList](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb),
[AutoPartsStore](https://schema.org/AutoPartsStore).
