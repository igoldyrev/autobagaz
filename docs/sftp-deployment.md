# Публикация на new.autobagaz.ru по SFTP

Для повторных публикаций используется скрипт:

```bash
scripts/deploy-sftp.sh
```

Он выполняет production-сборку, Pint и PHPUnit, сравнивает локальные файлы с
SHA-256-манифестом на сервере, сохраняет резервную копию заменяемых файлов,
загружает только изменения по SFTP, удаляет только отсутствующие локально файлы
из предыдущего манифеста, запускает миграции и пересобирает кеши
Laravel. Временный PHP-файл запуска создаётся со случайным именем и удаляется
сразу после выполнения.

Перед удалением таблицы `vehicle_body_types` скрипт автоматически сохраняет
её записи и связи с конфигурациями в `storage/app/deploy/backups` на сервере.

Пароль в проекте не хранится. Скрипт использует переменную
`JINO_SFTP_PASSWORD` или сохранённый профиль Jino в FileZilla:

```text
~/.config/filezilla/sitemanager.xml
```

## Обычная публикация

Сначала посмотреть список файлов:

```bash
scripts/deploy-sftp.sh --dry-run
```

Затем опубликовать:

```bash
scripts/deploy-sftp.sh
```

## Первый запуск

Если текущая копия уже вручную синхронизирована с сервером, создать исходный
манифест без загрузки файлов:

```bash
scripts/deploy-sftp.sh --initialize
```

Если состояние сервера неизвестно, выполнить полную загрузку:

```bash
scripts/deploy-sftp.sh --full
```

## Дополнительные параметры

- `--skip-checks` — пропустить сборку и тесты;
- `--dry-run` — ничего не изменять на сервере;
- `--full` — загрузить все разрешённые файлы;
- `--initialize` — только записать исходный манифест.

Локальные резервные копии сохраняются в игнорируемой Git папке:

```text
.codex/deploy/backups/
```

Скрипт никогда не загружает `.env`, локальную базу, `storage`, `public/storage`
или пользовательские файлы. Удаление ограничено файлами из предыдущего
deploy-манифеста и разрешёнными каталогами приложения; перед удалением файлы
скачиваются в локальную резервную копию.
