Монитор опубликован в репозитории Автобагажа, коммит `7546f956` ветки
`laravel-dev`, и установлен на VPS Aeza вне общего хостинга Jino.
Защищённый endpoint сборщика опубликован на `igoldyrev.ru`; код находится
в его репозитории, коммит `a8de3c9` ветки `master`.
Инструкции эксплуатации: [monitoring/README.md](../../monitoring/README.md).

## Реализовано и проверено

- `autobagaz-monitor.timer` включён и запускает проверку каждую минуту.
  Проверяются HTTPS главных страниц `new.autobagaz.ru` и `igoldyrev.ru`,
  а также свежесть сборщика через `/internal/monitoring/collector-heartbeat`.
- Время последней попытки сборщика читается без его обновления. Порог —
  15 минут; неудачный опрос источника также подтверждает работу сборщика.
  Подробные ошибки приложения остаются в существующем внутреннем мониторинге.
- Уведомление о сбое предусмотрено после трёх последовательных неудачных
  проверок, о восстановлении — после двух успешных. При продолжающемся сбое
  повтор — раз в час. Доставка сохраняется отдельно для каждого получателя.
- С Aeza отправлено одно тестовое сообщение через существующего бота сборщика.
  Telegram API подтвердил доставку. Секреты хранятся вне Git в закрытом
  `/etc/autobagaz-monitor/config.json`.
- Пройдены 8 Python-тестов: пороги, восстановление, напоминания, свежесть,
  повторы доставки, сохранение состояния и защита секретов в ошибках.
  В проекте сборщика пройдены 15 профильных PHP-тестов и Pint.
- На Aeza проверены unit-файлы systemd, ручной и автоматический запуск службы.
  После установки 22 обновлений ОС и перезагрузки на ядро `5.15.0-202-generic`
  таймер возобновил проверки автоматически. Повторная проверка журнала показала
  `autobagaz: ok`, `igoldyrev: ok`, `Result=success`, `ExecMainStatus=0`.
  Упавших служб нет.

## Границы проверки и оставшиеся работы

Реальные сайты и сборщик для испытания не отключались. Переходы в сбой,
восстановление и повторная доставка проверены автоматическими тестами;
на рабочем VPS проверены опросы, расписание и отдельное тестовое сообщение.
Проверка главной страницы не является проверкой всех страниц и сценариев покупки.

Актуальные журналы Apache не подключены и остаются в плане.
Отдельный контроль квоты аккаунта Jino исключён из плана по решению пользователя:
расход места проверяется вручную в панели, используются уведомления бота Jino.
Автоматический мониторинг самой Aeza пользователь исключил из задачи
и следит за ней самостоятельно.
