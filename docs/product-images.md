# Фотографии товаров и уменьшенные варианты

Исходные фотографии остаются в `storage/app/public/products/<товар>/`.
Поле `product_images.path`, имена файлов и содержимое оригиналов не меняются.
Размеры для витрины создаёт `ProductImageVariants` через штатный PHP GD с WebP.
Новых Composer- или npm-зависимостей нет.

## Размеры и вывод

Для каждого снимка создаются варианты с длинной стороной до 160, 480 и 960 px,
с сохранением пропорций, прозрачности PNG и поворота JPEG по EXIF. Маленькие
изображения не увеличиваются. Качество WebP — 85. Если полученный файл тяжелее
оригинала, для соответствующего размера используется исходный файл.
GIF и анимированные PNG/WebP остаются в исходном виде. Перед декодированием
проверяется доступный лимит памяти; слишком большой источник сохраняет прежний
вывод. При отсутствии GD или уменьшенного файла сайт также показывает оригинал.

Метаданные вариантов и SHA-256 источника хранятся в `product_images.variants`.
Файлы размещаются в подкаталоге `products/<товар>/variants/`, с ID изображения,
хешем источника и версией алгоритма в имени. Компонент `product-image` выводит
`srcset`, `sizes` и размеры изображения. У товара, карточек каталога и акций
используются варианты для текущего размера экрана; миниатюры галереи используют
малый вариант. При переключении фото обновляются источник, srcset, размеры,
подпись и ссылка на оригинал. Ссылка «Открыть фото в полном размере» и ссылки
без JavaScript ведут к исходным файлам.

## Новые и уже загруженные фотографии

Новые загрузки через существующий `ProductImageService` автоматически получают
варианты. Если обработка завершилась ошибкой, исходная фотография сохраняется
и показывается как прежде; ошибка создания вариантов записывается в журнал.
Удаление фотографии через админку удаляет её оригинал и связанные варианты.

Для уже загруженных снимков применяется миграция
`2026_11_02_020000_add_product_image_variants`, затем команда порциями:

```bash
php artisan products:optimize-images --after=0 --limit=20
```

В следующем запуске `--after` равен последнему обработанному ID из вывода.
Лимит — от 1 до 100. Повторная обработка готовых файлов возвращает `unchanged`;
отсутствующий вариант создаётся заново. `--force` пересоздаёт варианты принудительно.
Оригиналы команда не перезаписывает и не удаляет.

## Проверки

`tests/Feature/ProductImageVariantsTest.php` проверяет сохранность оригиналов,
размеры, прозрачность, EXIF, повторную обработку, новые загрузки, удаление
вариантов, вывод галереи и возврат к исходнику при отсутствии файлов.
Генерационные тесты требуют GD с WebP и EXIF; для полного прогона используется
лимит памяти 256 МБ, как на Jino:

```bash
php -d memory_limit=256M vendor/bin/phpunit
node --test tests/js/*.test.mjs
```
