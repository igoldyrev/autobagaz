# Внешний монитор на Aeza

Монитор запускается на `89.22.236.179` (SSH: `ssh -p 2233 root@89.22.236.179`).
Он проверяет HTTPS главных страниц `new.autobagaz.ru` и `igoldyrev.ru`, а также
свежесть работы сборщика через защищённый
`https://igoldyrev.ru/internal/monitoring/collector-heartbeat`.
Код endpoint находится в проекте `igoldyrev.ru`.

Подробные ошибки приложения, задач, очереди, диска и резервных копий остаются
в существующем внутреннем мониторинге. Внешний монитор не интерпретирует общий
`state` Автобагажа и не повторяет эти оповещения. Проверка главной страницы
подтверждает HTTP 200 и TLS, но не работу всех страниц и пользовательских сценариев.
Автоматическая проверка самой Aeza не предусмотрена.

## Правила

- Запуск раз в минуту; таймаут каждого HTTP-запроса — 8 секунд.
- Сбой после трёх последовательных неудачных проверок; восстановление после
  двух успешных. Время обнаружения зависит от момента сбоя относительно запуска.
- У сборщика проверяется `last_attempt_at`, порог устаревания — 15 минут.
  Ошибка источника также обновляет эту отметку: она не означает остановку сборщика.
  Чтение heartbeat не обновляет отметку. Выключенная интеграция, отсутствующие,
  старые или будущие отметки, неправильная схема и ошибки HTTP считаются сбоем.
- Сообщения через существующего Telegram-бота сборщика, с пометкой
  «Внешний монитор». При продолжающемся сбое — напоминание раз в час.
- Успешная доставка сохраняется отдельно для каждого получателя. При ошибке
  отправки — повтор на следующем запуске. Восстановление отправляется только
  получателям, которые получили сообщение о сбое. Сбой, восстановившийся до
  доставки, не создаёт устаревших сообщений. При неоднозначном сетевом сбое
  после принятия сообщения Telegram возможен дубль.
- Состояние сохраняется атомарно, параллельные запуски блокируются. История
  ответов и содержимое страниц не хранятся, размер состояния ограничен числом
  целей и получателей. Логи поступают в существующий systemd journal.
- TLS проверяется, редиректы запрещены, токен передаётся в заголовке. Ошибки
  не выводят URL Telegram, содержимое ответов или учётные данные. Прокси из
  окружения не используется: с Aeza запросы идут напрямую.

## Установка

Требуются Python 3.10+ и systemd 249+. Новых Python-зависимостей нет.
Сначала опубликовать endpoint сборщика в `igoldyrev.ru` и проверить его тесты.
Endpoint использует существующий `AUTOBAGAZ_MONITORING_TOKEN`; наружу выдаёт
только версию, идентификатор, текущее время, включённость и время последней попытки.

1. Скопировать `monitor.py` в `/opt/autobagaz-monitor/monitor.py` (root:root, 0644).
2. Создать `/etc/autobagaz-monitor` (root:root, 0700). Заполнить `config.json`
   по `config.example.json`, права root:root, 0600. Использовать действующие
   `MONITORING_TELEGRAM_BOT_TOKEN`, `MONITORING_TELEGRAM_CHAT_IDS` сборщика и
   `AUTOBAGAZ_MONITORING_TOKEN`. Секреты не добавлять в Git или аргументы команд.
3. Скопировать два файла из `systemd/` в `/etc/systemd/system/`.
4. Выполнить:

```bash
systemd-analyze verify /etc/systemd/system/autobagaz-monitor.service /etc/systemd/system/autobagaz-monitor.timer
python3 -B /opt/autobagaz-monitor/monitor.py --config /etc/autobagaz-monitor/config.json --check
systemctl daemon-reload
systemctl enable --now autobagaz-monitor.timer
systemctl start autobagaz-monitor.service
```

Служба запускается с `DynamicUser`, получает закрытый конфиг через
`LoadCredential` и хранит состояние в `/var/lib/autobagaz-monitor/state.json`
(с systemd возможна ссылка в `/var/lib/private`). Файл конфигурации не требует
доступа динамическому пользователю напрямую. Порты входящих соединений не нужны.

## Проверка и обслуживание

```bash
systemctl status autobagaz-monitor.timer autobagaz-monitor.service
systemctl list-timers autobagaz-monitor.timer
journalctl -u autobagaz-monitor.service -n 30 --no-pager
python3 -B /opt/autobagaz-monitor/monitor.py --config /etc/autobagaz-monitor/config.json --check
```

`--check` проверяет реальные адреса без отправки Telegram и изменения состояния;
код возврата 1 означает сбой хотя бы одной проверки. В обычном режиме выявленная
недоступность — успешно выполненная проверка; ошибка доставки даёт код 1.
Для явного теста доставки доступен `--test-notification` (отправит сообщение).
Здоровое состояние при запуске не создаёт уведомления.

После изменения конфигурации следующая активация службы загрузит новый файл.
Удаление состояния сбрасывает счётчики и память о доставке; не делать этого
при обычном обновлении. При повреждении состояния служба завершается с ошибкой,
а не начинает молча с пустого состояния.

Остановка и откат:

```bash
systemctl disable --now autobagaz-monitor.timer
systemctl stop autobagaz-monitor.service
```

Удалять состояние и конфигурацию для остановки не требуется. При обновлении
сохранить прежний `monitor.py`; таймер и конфигурация не затрагивают другие
контейнеры и службы Aeza.

Локальные проверки:

```bash
python3 -B -m unittest discover -s monitoring/tests -v
```
